# Session notes — 2026-06-10: throughput, terminal play, and the staller fix

Working session summary (Conor + Claude). Two stated objectives: (1) engine/training
throughput ("500 battles/sec is not impressive"), (2) agent strength + better evaluation
metrics — motivated by Conor easily beating the best agents in the browser.

## 1. Throughput — solved (~4.5x training, ~12x rollouts, ~5x search)

Profiling showed the C++ engine at ~263k turns/s with **Python `build_state`/`featurize`
eating ~80% of rollout time**. Fixes (all parity-tested, all merged to main):

- **C++ observation encoder** (`engine/src/encoder.cpp` + `encoder.hpp`): `encode_batch`
  (padded numpy feature tensors), `step_pair` (reveal bookkeeping + step),
  `select_heuristic` (C++ twins of MaxDamage/SmartHeuristic/Staller), `search_leaves`
  (decision-time search's whole leaf loop in one call). Static data is registered from the
  same poke-env tables Python uses (`engine_cpp.register_encoder`, auto-run by
  `StaticData`); `tests/test_encoder_parity.py` asserts **bit-identical float32 features**
  (including Python 3.12 `sum()` Neumaier compensation) and decision-identical heuristic
  picks. `tests/test_search_fast.py` pins fast search == slow search per decision.
- **Factored net layer 1** (`ActionScorer._layer1`): global half computed once per state,
  not per action row — same parameters/checkpoints, ~2x faster PPO updates.
- Numbers on the ThinkPad (16 cores, no GPU, batch=256): training ~100 → **~450
  battles/s** end-to-end (PPO backward is now the floor; torch's 8-thread default is
  optimal — 16 threads is 12x WORSE), rollouts/evals → **~2,200 battles/s**, search ~5x.
- Bit-rot fixed along the way: `eval_ckpt.py` (KeyError'd at HEAD), `test_recon.py`
  (status-case asserts).

## 2. Terminal play — `agent/play_cli.py`

Interactive battle on the in-process C++ engine (no server/browser): numbered action menu
with type/power/acc/effectiveness, effect tags + WILL-FAIL hints, switch matchup risk;
partial information both ways; clauses on by default; `--show-eval` prints the agent's
win-prob. Pilots: `raw` (default, measured strongest vs humans) / `search` / `heuristic` /
`staller`. Conor's team: **`teams/gen1ou-conor.txt`** (standard six, Alakazam lead).

```sh

```

## 3. Strength + metrics — measured findings (don't relitigate)

- **Search lift is checkpoint-dependent and currently NEGATIVE**: for both fresh nets,
  1-ply search (any config, incl. minimax + calibrated leaf) is -6..-14% vs the staller and
  ~0..+8.5% vs the smart attacker. Patient humans play staller-shaped → `play_cli` defaults
  to the **raw** pilot.
- **Expert iteration has no signal while the teacher isn't stronger**: 6 v3 rounds from
  `models_fast/pg_best`, zero accepted (the monotone gate reverted every round). Check
  `search_eval` lift before spending an expert-iter run.
- **The staller hole was a training-distribution hole**: self-play + smart anchor never
  shows patient para+recover play. `train_engine --anchor staller|mix` fixes that, evals
  print a vs-staller line, and `pg_best` is gated on the smart+staller MEAN.
- **Ladder upgrades** (`ladder.py`): staller baseline by default + `--search-ckpts` rates
  search-piloted checkpoints (SearchPilot) on the same Elo scale.
- **Calibrated value net**: `value_fast/value_best.pt` (Brier 0.111) — trained on the OLD
  policy's games; retrain when promoting a new net if search is revisited.

```sh

# the deciding comparison once it's done:

    --battles 150 --clauses --hidden 256   # NB: per-player hidden differs — see note below
```

NB: `ladder.py` has a single `--hidden` flag; to ladder a 128-net against a 256-net,
run two `eval_ckpt`/`search_eval`-style evals instead, or extend `_load_net` to read the
hidden size from the checkpoint (small TODO).
